updated: 2026-07-17T21:25

- (direction) User wants DEMO mode and REAL mode. DEMO: real-time data only, never executes buy/sell. REAL: all features including execution.
- (capability) CAP-1: User switches between DEMO and REAL mode via UI toggle. When REAL mode is selected, the app confirms intent before enabling execution.
- (capability) CAP-2: DEMO mode shows real-time Binance market data, strategy signals, backtest results, scoring, news, agent analysis — everything except order submission.
- (capability) CAP-3: REAL mode activates PaperEngine execution on real Binance market data. Still paper execution (MVP) unless a live exchange adapter is plugged in.
- (capability) CAP-4: Mode-persistent configuration survives restarts. User preference for demo/real is saved to .env or config.
- (constraint) REAL mode MUST require explicit opt-in via env var (ALLOW_LIVE_TRADING=1). In-app toggle only switches between paper-demo and paper-real.
- (constraint) All Binance data collection uses public no-auth endpoints. No API key stored.
- (constraint) UI must visually distinguish DEMO vs REAL mode at all times (badge, color, label). User must never confuse which mode is active.
- (constraint) Frontend exists as a single codebase. Mode toggle just changes execution behavior — same pages, same API endpoints.
- (non_goal) Real-money Binance exchange adapter is a non-goal. REAL mode means paper execution priced at real market data.
- (non_goal) Multi-user auth, permissions, or team workspaces are non-goals.
- (assumption) Assumed the user wants a single toggle in the sidebar, not separate installs or branches for demo vs real.
- (assumption) Assumed DEMO mode is the default. REAL mode must be explicitly enabled by toggling AND confirming.
- (note) Current codebase: core/execution.py already supports mode='paper'|'live' with ALLOW_LIVE_TRADING guard. core/paper_engine.py runs paper fills against live Binance ticker. Frontend Dashboard.tsx has hardcoded mode='paper' state.
- (note) All paths analyzed: market (REST data), paper_engine (paper orders), execution (mode switch), strategy_api (REST API), frontend Dashboard (tab navigation, sidebar). Everything is wired through /api/*. No separate FE builds.
- (note) DEMO mode: all /api/* endpoints respond normally EXCEPT /api/orders returns error 'demo mode — no execution'. /api/positions shows empty. /api/health reports mode=demo.
